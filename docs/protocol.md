# Modbus 协议与寄存器

当前代码：115200 bit/s，8N1，默认从站地址 1。支持标准功能码子集 0x03、0x04、0x06、0x10；私有扩展为 0x41。以下地址均为报文中从零开始的地址。

## 输入寄存器：0x04

| 地址 | 数据 | 编码 |
| --- | --- | --- |
| 0x0000 | 温度 | int16，0.01 ℃ |
| 0x0001 | 湿度 | uint16，0.01 %RH |
| 0x0002 | 模拟量 1 | uint16，mV；来自当前电压快照 |
| 0x0003 | 模拟量 2 | uint16，mV；来自当前电压快照 |
| 0x0004 | 设备状态 | 见下文 |
| 0x0005 | 数据有效位 | bit0 温度、bit1 湿度、bit2 模拟量1、bit3 模拟量2 |
| 0x0006～7 | 本次开机时间 | uint32，毫秒，高16位在前 |

状态位常量：bit0 报警；bit1 日志就绪；bit2 存储故障；bit3 传感器故障。注意当前 `Modbus_UpdataInputSnapshot()` 的存储异常路径实际设置 bit3，未使用 bit2；主站与固件应统一后再定版协议。

当前实时模拟量寄存器来自最新数据对的电压快照；日志中的模拟量是 100 点均值的原始 ADC 值，两者单位和处理路径不同。

## 保持寄存器：0x03 / 0x06 / 0x10

| 地址 | 内容 | 默认值与范围 |
| --- | --- | --- |
| 0x0000 | 温度上限，int16，0.01 ℃ | 默认 3100；-4000～12500 |
| 0x0001 | 回差，uint16，0.01 ℃ | 默认 100；1～5000；上限减回差不得低于 -4000 |
| 0x0002 | 日志间隔，秒 | 默认 5；1～60 |
| 0x0003 | 从站地址 | 默认 1；1～247 |
| 0x0004 | 参数保存命令/状态 | 单独写入 0xA55A 申请保存；读回状态 0 空闲、1 忙、2 已保存、3 错误 |

修改配置后须显式保存才会持久化。保存命令不能与普通参数混在一次多寄存器写入中。回复成功表示请求被接受，最终保存结果要轮询状态。

## 帧、异常与边界

- CRC-16 低字节先发；多字节寄存器数据高字节先发。
- 接收路径使用单字节中断、环形缓冲与定时器间隙检测；当前 TIM2 配置名义间隙为 1.75 ms。
- CRC 失败在 Modbus 任务中丢弃；地址不匹配不回复。0 地址广播不回复，支持的写功能按代码规则处理。
- 合法寻址请求的异常码包括 1 不支持的功能、2 地址非法、3 数值非法、4 执行失败、6 设备忙。
- 串口错误、队列溢出后有丢弃与重新同步路径，实际恢复表现需做异常注入测试。

## 私有扩展 0x41：按序号读取单条历史

请求为 8 字节：`地址 41 序号[31:24] 序号[23:16] 序号[15:8] 序号[7:0] CRC低 CRC高`。

正常回复为 21 字节：地址、41、字节数10(hex)、16字节内容、CRC低、CRC高。内容依次是记录序号 uint32、开机毫秒 uint32、温度 int16、湿度 uint16、ADC1 原始均值 uint16、ADC2 原始均值 uint16，均为高字节先发。

该分支通过 `Storage_ReadHistory()` 将历史读取请求提交至存储请求队列，由 `StorageTask` 统一执行 Flash 访问，并通过回复队列返回结果。日志写入、配置保存与历史读取在同一存储任务中串行处理；读取接口使用请求编号匹配回复，避免超时后迟到的旧回复被后续请求误用。详见 [任务设计](architecture.md)。

当前 0x41 调用的等待超时参数为 **1500 ms**。存储忙、请求队列满或等待超时返回异常码 **0x06**；其他读取失败返回 **0x04**。请求编号与超时处理已在源码中实现，实际并发运行与超时恢复表现需结合硬件测试记录。

普通 Modbus 调试软件未必支持私有功能码；当前资料未附 CSV 批量导出上位机程序，因此这里提供的是“按序号读取单条历史记录”的固件接口。
